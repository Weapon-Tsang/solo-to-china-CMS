# SoloToChina Content Production Strategy 2.1

状态：active；生效日期：2026-09-11。应用 1.18.3；schema 56。唯一版本清单为 `config/content-strategy.json`。

## 一、操作界面只有一次文章决定

“建议”是唯一的人工文章批准入口。管理员批准多少篇文章，“内容”页就逐篇显示多少条记录，并单独统计已经创建的内容数量。未完成的记录必须直接显示中文原因与最小处理入口，不再展示上下两套含义重叠的队列。

原“创作规划”菜单、人工命题接口和专用代码已移除。文章获批后，系统仍可在内部自动整理证据、文章结构和页面结构；这些属于生产实现步骤，不是面向运营人员的第二套功能或第二次审批。

## 二、来源事实采用信任输入原则

管理员主动选择的来源是本次写作的可信输入。来源中的日常票价、营业时间、预约、交通和开放安排可以按原文使用，不要求再查官方页面，不设置人为的发布日期门槛，也不因为缺少日期自动阻塞。

只有同一对象、同一条件和同一适用时间下不能同时为真的信息才形成冲突。真正冲突按事实组持久化为一次人工决定；不同作者的路线、选择、观察或互补细节允许并存。安全、法律和高后果事实继续保持严格边界。

## 三、原图、文字与图片关系

采集必须保存正文、真实图片文件、图片哈希、实际 MIME、页面顺序、图片说明、附近文本和图片到信息主张的关系。远程 CDN 地址只作来源追踪，不能冒充已交付文件。GIF、JPEG、PNG 和 WebP 以实际文件签名识别，旧的失效链接不得一律误诊为图片 403。

写作前先从已授权、已落盘且与本文证据相关的图片中选择候选。匹配只依据图片自身的替代文字、说明、附近文本和关联证据，不能因为来源标题相似就继承图片身份。需要实景的对象不得用生成模型伪造。

如果被选原图包含中文，图片模型必须接收原图，只翻译清晰可读的中文文字。场景、人物、物体、建筑、食物、路线几何、裁切、透视、光线、颜色、标志与非中文标签都必须保持不变；无法识别的文字保持原样。原图和翻译派生图分别留存并可追溯。

## 四、正文与交付独立检查

正文质量审核只判断英文表达、事实支持、证据边界、冲突披露、内部信息泄漏和商业污染。图片下载、图片生成、页面编排、组件契约和 WordPress 传输属于交付检查，不得降低正文质量分，也不得触发无关正文重写。

正文审核可以和图片处理、页面编排并行。只有正文通过且当前页面和媒体均可交付时，系统才继续商业组合和 WordPress 草稿投递。任何线上发布仍需人工确认。

## 五、内容结构与修复

文章采用简洁、实用的英文指南风格，不为字数填充无证据内容。简短提示建议 200–400 词，窄主题 350–700 词，一日路线或清单 600–1000 词，多日及综合指南 900–1400 词；这些是软性编辑范围。

有界修复只提交失败字段、相关章节及其完整证据，不按数据库顺序截取“前若干条”事实。金额、日期、否定、适用人群、条件、例外、原句和限定语必须完整保留。

内容 AST 的每个无匹配章节从空证据状态开始，不能继承上一章节的证据台账。有序列表保留顺序；已选媒体形成带来源素材引用和交付媒体 ID 的独立节点。页面组合优先消费稳定组件和这些结构化节点，不能把文章重新压平成固定模板。

## 六、中文诊断与移动端操作

所有运营可见的错误标题、状态、按钮、建议和确认对话框使用直白中文。原始英文错误和内部代码只保存在日志中。质量问题字段缺失或格式异常时，也必须显示非空的中文原因和处理建议。

所有危险或高影响操作使用站内响应式对话框，不使用浏览器原生 `alert`、`confirm` 或 `prompt`。对话框在手机上提供足够触控尺寸，并明确说明将保留的正文、来源、图片和版本历史。

## 七、不变的安全边界

来源选择保持人工主导，不绕过访问控制或平台验证。Research Draft 与 Commercial Composition 保持隔离。WordPress 只接收经过完整交付检查的草稿，系统不自动发布线上文章。前端组件能力仍由版本化契约提供，CMS 不发明组件、属性或视觉样式。
