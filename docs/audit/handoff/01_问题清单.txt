如何在另一个账号使用
推荐方式：将“01_问题清单.txt”和“02_完整修复提示词.txt”上传到新账号的同一任务，发送：
“请读取这两个文件，按总提示词和建议批次执行全部修复及优化，持续更新 repair-progress.md，不要只给计划。”

分批方式：先发送总提示词，再按批次粘贴对应 A/B 条目。若开启全新任务，可上传 ZIP 内“逐项提示词”中的对应 TXT；每个文件都包含仓库、基线、通用约束、问题描述和验收，不需要前一个账号的聊天记录。

节省额度：优先完成批次一至四的 A 类缺陷；B 类是已纳入任务范围的优化，继续在批次五执行。跨账号中断前要求保存 repair-progress.md 和精确下一步，不重复从零审计。

各提示词允许修复所需的代码、测试和迁移；不等于授权生产部署、破坏性数据操作或任意付费请求。

请把内部证据映射转换为读者可理解的官方出处、核验日期、条件与例外；为价格、预约、支付和安全信息提供恰当来源链接。保留 source ID 内部追踪但不泄漏研究元数据。使用真实作者/组织与审核信息，不能虚构经历。与 A09/A11 的证据日期和页面输出共用数据。验收：关键事实可追至真实 URL 和证据版本，原文例外未丢失，内部 src/claim 标识不进入可见页面。



B03  校正 GEO 与 FAQ 搜索策略

请核对修复当天 Google 官方 AI 搜索与结构化数据文档，修订 GEO/SEO 规则，去除 FAQ 富结果、固定字数、llms.txt 或 schema 必然带来引用排名等承诺。原审计核对的官方记录说明 FAQ rich result 自 2026-05-07 起不再展示；执行时重新核对并记录来源日期。FAQ 仅在满足真实问题时生成，结构化数据与可见内容一致。验收：提示词和质量门禁不再为不存在的搜索特性强制填充内容，也不删除有用 FAQ。



B04  支持已有文章更新合并和退役

请将内容机会区分 create/update/merge/retire，建立 Claim→文章→已发布 URL 的反向影响索引。新增证据与已有文章重叠时可创建定向更新建议，不仅因标题相似而 dismissed。更新发布策略继续尊重已发表文章保护：默认产生更新草稿/差异供审核，不能直接覆盖已发布正文。验收：票价变化产生指向正确文章的更新机会，重复来源不会重复建稿，update 审批与 create 身份清楚，退役只提出受控建议。



B05  稳定内容块与真实内部链接

请用稳定 block ID、语义角色、来源和修订记录表达页面内容，优先确定性映射已审核文案。内部链接仅从已发布页面库存解析，按实体、意图、目标可用性与自然锚文本选择；不要让模型猜 URL。处理草稿链接、404、重定向、重复锚点和文章自身链接。验收：重排不丢证据身份，相关链接可解析且不指向测试或未发布页；与 Commercial 定位索引不冲突。



B06  在租约安全后增加有限并发

请在 A16 和版本门禁完成后，为任务 DAG 提供按 provider 受限并发、独立图片队列与公平调度。保持同实体同修订写入串行；长模型任务不能阻塞健康检查或全部短任务。支持可配置默认保守并发、背压、停止和恢复。验收：模拟慢请求期间其他独立任务可前进；同一阶段不重复领取；限流不形成重试风暴；并发提高后的费用和资源使用有测量。



B07  记录模型成本并按任务分配预算

请记录每阶段模型、prompt/schema 版本、input/output/cached token、耗时、重试、估算费用和最终 QA 结果。usage 缺失记 unknown，不能记零。价格表来源和时间可配置，费用仅标估算；不假设各提供商相同。提供按每篇 QA 合格文章聚合的成本与延迟，并允许抽取、规划、写作、审阅分阶段配置模型/思考预算。验收：从 mock usage 可正确汇总重试费用，无密钥/全文进入日志；模型切换有评测依据，不强制换更贵模型。



B08  缩小提示上下文并缓存稳定阶段

请建立阶段专用白名单 DTO，去掉 raw JSON 与解码对象重复传输、无关城市事实、旧 review/publish/commercial 记录。Research prompt 不应接收历史商业组成。按 source/证据 hash、模型、prompt version、schema version 和策略版本构建缓存键，明确变更失效与失败不缓存策略；图片/视频处理缓存同样追溯。验收：同输入重跑减少调用，事实/策略变更命中失效，文章间或来源间不串缓存，审计可看到输入规模与命中率。



B09  按错误类型恢复任务和契约

请统一结构化错误分类：429/503 使用 Retry-After、指数退避和 jitter，401/403 与确定性 Schema 错误停在需处理状态，格式错误有界修复，资源缺失走补证/素材任务。契约同步成功后定向恢复受 stale_contract 阻塞的页面并重新校验当前版本；检查 snapshot 身份是否只依赖 Registry checksum 而遗漏 Page/Publish Schema 变化，如存在则修复不可变 provenance。验收：永久错误不烧完多次相同调用；契约更新不会永久卡死或无限重编排；旧快照可追溯；失败原因可操作。



B10  建立跨仓库最终产物验收门禁

请把两个仓库的真实生成契约、Schema 转换、版本 QA、故障恢复、WordPress 保存编辑渲染串成隔离验收。至少覆盖真实 Registry 样例、模型错误输出、缺模态、缺图、响应丢失、并发幂等、编辑后 FAQ/schema 与 canonical。mock 可验证调度但不能冒充真实模型/PHP/浏览器结果；提供有环境时可执行的最小真实 smoke。验收输出区分 PASS/FAIL/NOT TESTED，记录代码版本和命令。真实外部测试缺凭据时标已实现待外部验证，不能整体报全部完成。
