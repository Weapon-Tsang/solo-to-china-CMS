## Reading composition policy

The composer does not assign a component quota and does not select a fixed template from `content_type`.

| Reader task | Simplest eligible representation | Placement reason |
|---|---|---|
| Continuous explanation | `paragraph` | Avoids turning ordinary prose into cards. |
| Immediate answer | `quick_answer` only when the plan identifies a genuine answer block | Gives the answer before optional actions without duplicating hero/summary. |
| Compact facts or takeaways | `quick_facts` / `key_takeaways` | Used only for independently scannable facts. |
| Ordered action | `steps` / `checklist` | Preserves order and keeps the group indivisible. |
| Travel sequence | `route_timeline` | Requires route/order semantics; ordinary metro wording does not create a train product. |
| Risk or prerequisite | `warning` before the affected action | Keeps restrictions and negative conclusions visible before CTA placement. |
| Helpful contextual advice | `tip` after the related explanation | Does not interrupt the answer. |
| Real comparison | `comparison_table` | Used for table/comparison semantics, with local table scrolling on mobile. |

Each enhanced choice carries an internal reader job, source node/section binding, placement reason and fallback reason. Those audit fields are not injected into undeclared public block data. Media and commercial anchors are rebound after composition rather than copied by array index.

```powershell
npm run repair:delivery -- --db <disposable-work.sqlite> --scope commercial --draft <approved-draft-id> --development-copy --apply
```

Direct database production mutation remains impossible through the script's advertised apply path: `--apply` requires `--development-copy`.
