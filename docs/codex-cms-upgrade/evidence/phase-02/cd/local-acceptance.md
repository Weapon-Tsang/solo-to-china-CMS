# 阶段02 C/D 本地验收与外部门禁

2026-09-28。结论：**PASS_LOCAL(CMS_ONLY)：C_LOCAL_ACCEPTED、D_LOCAL_ACCEPTED（CMS 本地与受控接收器协议范围）**。A2_LOCAL_ACCEPTED、B_LOCAL_ACCEPTED 及先前未提交成果保持。此结论不表示真实 WordPress 已更新、真实 AI 质量已验证或阶段03获授权。应用版本 2.0.70，原 HEAD `490dd7464d4beb46d3f89a578337c253917fbf7a`；本地新 schema 83。无 commit、push、部署、生产写入、收费模型调用。

## 已实现的行为

- C：按真实原图像素与来源关系审计封面，分页查看；记录焦点/安全裁剪、生成独立 16:9 衍生图；文章实拍、已有同对象库存与抽象编辑插画分流。预览、确认、版本锁、撤销和追加历史均不改正文。必需封面缺失阻止交付。内部 `card_title` / `deck` 随一次 article bundle 生成并保存，严格合同不支持时不外发。封面接收器协议有当前页面/文章/特色图身份校验、幂等和未知结果对账；未连接真实接收器。
- D：文章详情和内容生产异常详情可就地上传；多选、拖入、8 MiB 分块、暂停、刷新后重选同文件续传、逐项回执与私有预览。人工来源、不可变原件、采用锁、独立媒体修订/冻结清单、局部恢复、撤销与跨目录备份可追溯。文字图及路线图保留独立审查或证据等待；普通实拍先做本地 OCR/质量及衍生图，不因此调用付费模型。只有被明确选择的图片进入新媒体修订；页面合同容量超出时阻止采用并显示差额，原件继续保存。已发布文章正文媒体刷新只允许具备精确能力和旧页面身份的接收器执行；当前没有该接收器，外部交付等待。
- 所有手动选图/衍生图仍受当前 revision、原件 hash、槽位用途、人工锁和旧 Worker 迟到结果保护。选封面不挤掉正文图片；正文文字、SEO title、slug、内容 hash、写作包和既有模型预算不因补图重写。

## 操作和交接

管理员在文章或异常详情点“上传图片补齐”→选择/拖入图片→查看服务端预览、槽位与仍缺的项目→“确认采用并继续”。刷新或断线后重新选择相同文件，服务端先核对 hash 和已确认分块。取消/撤销保留审计和原件。普通实拍可在 CMS 本地继续，信息图/路线图及外部接收受各自明确门禁，界面不把“已保存”写成“已上线”。

schema 83 需在阶段03/04预检中将旧应用打开新数据库视为不兼容；只能用包含 DB、原件、暂停分块、修订与媒体映射的完整快照恢复，经 migration-review 核对后交接，不能直接让旧 schema82 代码写新库。回放仅对既有获准 work 副本做外层事务与回滚，不构成实际历史数据迁移。详见[阶段03/04预检记录](phase-03-04-precheck.md)与[外部依赖](../../../EXTERNAL_DEPENDENCIES.md)。
