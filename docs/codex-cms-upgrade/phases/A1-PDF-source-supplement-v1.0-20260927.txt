二、原规范与本轮成功定义

原BIND-011的核心要求：
模型能看见PDF某页，不等于素材库有可发布的单图文件；可可靠提取时保留独立资产及PDF页/对象/区域来源；不能可靠分离时明确原因并提供人工上传对应图片入口，不伪造JPG。
T02-46原场景：PDF中的图可被模型读取，但没有独立文件；按结构可提取则留来源，不支持时有明确原因和可用人工补图。

本轮固定走人工补充这一受允许的分支，成功必须同时满足：
1. PDF仍作为原始文档证据保留，不被重命名、覆盖或冒充照片；自动提取能力如实显示。
2. 真实用户操作入口可以接收独立图片字节，服务端确认已保存后刷新，而不是只有文字提示或未来按钮。
3. 新图片有自己的身份、原件、hash、MIME、尺寸和可追溯的来源补充关系。
4. 确认来源对应关系后，符合现有证据规则的图片可以进入现有实体/来源素材候选检索和规划输入；模糊或冲突仍保留状态。
5. 全程不自动改已确认正文、冻结写作包、文章图片、生产任务和预算；不是D文章采用或续跑。
6. 文件与关系可恢复，原始PDF和旧记录不被删除。

本轮不要求：所有PDF格式都能自动抽图、每张PDF图都自动命名地名、整页OCR、全本高分辨率渲染、生成实拍替代图、跑完真实路线文章、调用真实模型或发布WordPress。

三、产品流程：使用已有来源详情和媒体诊断入口

1. 在当前PDF来源详情/媒体诊断中增加“为这份PDF补充图片”或含义一致的按钮。
   不在当前阶段开发新的全局素材后台、文章槽位工作台或大表单。
   接口返回真实capability；入口存在但服务端不可用时不能谎称已支持。

2. 点击后自动携带已核实的source ID、capture/version、PDF asset ID和PDF hash。
   这些上下文由服务端校验，不能只相信前端隐藏字段；用户不需要手工填写ID或本地文件路径。
   支持选择独立图片并追加，展示上传/服务端确认/已保存/待确认/失败状态。
   复用现有上传协议和文件选择组件；不要改全站视觉或公开前端。

3. 来源补充只需一次明确确认：图片与本来源的对应方式，及有依据的页/图注/实体。
   复用现有实体选择、关系预览与证据定位能力。已有明确上下文自动带入，用户确认即可，不要求逐图重做采集/提取/审批。
   未知页码可以不填，并标明“对应页未确认/仅来源话题补充”；不猜页码或object ID。
   已知页码必须验证范围；图片属于另一PDF或另一版本时不能静默关联。

4. 服务端确认原件与记录成功后，更新当前来源局部状态，展示可打开的图片预览、用途及关系。
   不依赖用户手动刷新；刷新/切菜单返回后仍能看到。
   网络上传100%不等于入库完成；尚待commit/receipt时保留明确状态。
   文案明确：“已加入来源素材，尚未替换文章配图”。不能显示“文章已恢复生产”。

5. 继续采用原有关系证据和用途规则。
   仅上传并确认“补充给此PDF”不等于确认精确地点；页面/图注/管理员明确对应能提供多少依据就使用多少。
   人工确认优先于纯像素无法命名，但不覆盖实际冲突、撤销、过期、损坏文件和类型不符。
   不把所有补图绑定到PDF标题地名，不制造Claim来获得素材检索资格。

四、实现：一次共用接收、两类来源身份，不造假谱系

1. 优先复用现有capture-media-uploads、原件journal/receipt、source-assets和来源关系服务的等价路径；先查实际签名与语义，不按本文硬造同名端点。
   可新增窄范围的来源补图提交动作或适配器，但不要复制新的分块协议/另建媒体文件库。
   原采集接口若只能覆盖完整来源，不得为了补一张图重写整份source/capture；用追加的补充出现位置/关系记录完成。

2. 每张图保存自己的asset ID、原始字节hash、真实类型与尺寸、接收会话/receipt及状态。
   保存source/capture/PDF关联、可核实的页/区域/图注、操作者、确认时间、关系版本和幂等身份。
   字段名沿用现有模型；新增字段采用最小向后兼容变更并有真实迁移回归，不擅自重构数据库。

3. 区分两种谱系：
   - 已有自动抽取路径：确实从PDF对象或区域产生的文件，记录提取器版本与真实定位。
   - 本轮人工补充路径：记录人工上传及“补充给该来源/用户声明对应某页”，不得写成“系统从PDF提取”。
   人工上传文件hash不能写成PDF hash；来源关联不是字节派生关系。
   来源文件与补图各自保留；正文/图注中的证据名称与关联范围准确。

4. 图片文件类型和“是不是实拍”分开：
   JPEG/PNG只证明编码，不证明拍摄身份。整页截图、路线拼图、信息图仍按对应角色保存。
   不因转成PNG/JPEG或管理员选择了一份PDF，就将它自动标为精确场景照片。
   原有照片用途限制与封面规则不因补图而关闭。

5. 大文件和数量处理继续复用现有有界并发/分块/续传，不能新设固定10张/20MB等业务限制来图省事。
   真实存储空间、协议请求大小和解码保护继续有效，错误说明具体原因并保留已完成项。
   现有诊断的32MiB/40MP等检查预算不是人工上传业务上限，不能未经区分直接继承成拒绝上传规则。
   不为本任务重新完成D的101文件全矩阵或性能专项；只验证本次接入未绕开既有协议与数据保全。

6. 并发与失败：
   文件接收已成功但最终响应丢失，按receipt/幂等键查对，不重复创建同一次来源补充记录。
   同一图片可在不同来源/页具有不同出现位置；物理字节可以复用，但上下文不能被去重抹掉。
   过期预览、PDF版本/hash改变、来源删除或权限改变时拒绝旧确认，不借旧预览覆盖新状态。
   中途失败保留已有原件/接收记录；未完成补图不得标ready，不删除历史文件腾空间。

7. 安全范围：
   复用现有CMS管理员认证、Origin/CSRF与运行模式校验，不开放匿名上传、不通配CORS。
   服务端校验source/capture/asset所属范围；不接受客户端任意磁盘路径，不跨数据根读写。
   migration-review按原模式拒绝写入，正常开发仅使用隔离数据集；不得以补图按钮绕过模式权限。
   不执行PDF内的指令/脚本/外部链接，不新增外部OCR或生成服务。
