4. 新版本若把同库同云主原地更新错误地当成“新主机接管”，先按实际规则核实，不运行local:promote或伪造身份来跳过未知任务保护。真实安全条件不满足就停相应自动消费并说明，不设置ignoreUnknown。
5. API健康与Worker能工作分别报告。后台可登录但Worker不允许正常领取任务时，不得写“云端生产已恢复”；可精确写“后台升级完成、生产队列仍受某条件限制”。
6. 同一逻辑任务只有有效租约的消费者工作，旧版本退出、新版本接替有证据。不要因为沿用云端就启动本机第二个Worker。

九、域名、扩展与有限上线验证

【原域名验收】
- 通过原来的CMS完整HTTPS地址打开后台，核对证书/登录和真实API，确认页面不是旧缓存或本地代理。
- 读取实际runtime版本/commit/schema，确认数据库身份和数据根仍在既有云端；只在受限交接中记录内部路径。

- 验证访问和云端任务不依赖本机候选进程；通过部署配置/网络路径及已停止本轮本地测试进程后的域名访问确认，不关闭用户电脑或其他原服务。

【有限写入冒烟】
- 先选用非敏感合成文字与真实生成的测试图片；图片明确测试/示意用途，不冒充景点实拍，不借假QA穿过必需事实图门禁。
- 用现有认证API/真实后台在CMS创建最多1来源、1测试草稿、3张图片，验证分块→持久回执→刷新→来源/媒体记录→指定草稿的合法确认；标记测试用途并保持不公开。

- 没有真实支持的安全接口，或该场景必须发生未获准模型调用，则不执行对应写；标明该功能未激活，保留其他兼容成果，不能假称端到端完成。

【浏览器扩展】
- 产出当前修复版扩展包/明确加载目录、版本和hash；版本由实际代码确定，不强制回到历史2.0.71。

十、失败处理与可回滚边界

1. 部署前遇到未支持schema、坏备份、错误目标、失效密钥、无持久卷或无法安全升级，保持旧生产，不带风险上线。
2. 发布导致真实故障，先停止本次受影响写入/任务领取，保留新记录和回执；不要用重启/全部重试掩盖错误。
3. 旧代码确认能读写当前schema时，可恢复已保留的旧制品与兼容配置；若不能，绝不让旧程序直接写新库。
4. 仅在新版本尚未接受任何不可丢业务写入、没有新的远端副作用，且本次维护范围内核实满足条件时，允许恢复本轮部署前完整备份。已接受新数据/产生远端结果后不得自动全库倒回覆盖；保持安全状态并输出精准差异与恢复方案。
5. 回滚不改公开前端、不降级固定合同校验、不删新人工原件、不清预算、不释放unknown。保留备份、旧制品和所有失败证据。
